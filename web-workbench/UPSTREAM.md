## Build-time delivery adaptations

The delivery adaptations do not modify vendor files on disk or the raw engine/font cache. The selected upstream backport is recorded separately below. `scripts/build.mjs` applies a narrowly scoped Vite transform to the four literal font URLs in the pinned editor entry, from `./cjk…` to `./compressed/cjk…`; each expected literal must occur exactly once. Basenames, complete font bytes, family aliases and injection timing remain unchanged. Brotli quality 6 representations are generated beside retained original files. `representation-manifest.json` distinguishes encoded transfer hashes from decoded original hashes; build and release verification decompress every font and compare it with the original `asset-manifest.json` pin. Only the explicit `editor/compressed/` URLs receive `Content-Encoding: br`; old original paths must never receive that header.

No preload hints are injected for the large runtime/font resources. The earlier parallel HTML preloads were withdrawn after two of three production cold-start trials failed with stalled transfers; the underlying transport failure is not yet diagnosed, and withdrawal is not proof of resolution. Mutable URLs stay revalidated; no immutable caching is introduced.

`scripts/runtime-transform.mjs` now adapts four exact blocks in the pinned boot source, rejecting missing or duplicate insertion points. It starts the first-party `src/runtime-transport.js` adapter before font fetching, waits for its results after the complete-font gate, supplies the pinned Emscripten `instantiateWasm` and synchronous `getPreloadedPackage` hooks, and connects disposal. WASM is immediately consumed by `compileStreaming`; data is immediately consumed into a decoded buffer. Metadata remains fetched by the native package loader, whose expected size is checked before handing off the buffer once. Font injection, aliases, native worker startup and native document behavior remain unchanged. The distributed vendor files and engine bytes remain hash-verified.

The adapter requires the existing Brotli and MIME contract, fails explicitly on invalid delivery/compilation/package size, aborts remaining fetches on failure or disposal, and observes early rejections while fonts are pending. It releases its decoded-buffer reference at handoff and ignores compilation/instantiation completing after disposal. Runtime failures do not trigger a second or raw-byte download. This changes consumption scheduling; it is not evidence that the earlier transport failure is fixed or that production cold starts meet ten seconds. Tests exercise the real generated iframe and native editing/export separately from synthetic transport failures. All adapter sources, transforms and tests are included in `source.zip`.

For deployment/rollback overlap, the build also replaces exactly the pinned font fetch block with the first-party `src/font-transport.js` adapter. Correct Brotli responses follow the normal path; missing/wrong encoding headers, failed requests or body decoding failures fall back to the retained original font URL. A rejected response body is canceled before fallback. If both representations of a required bundled font fail, startup fails explicitly instead of continuing with a missing family; optional system-font behavior is unchanged. The same full font bytes are injected at the same native startup point. This is a delivery adaptation, not a font subset or native editor fork; the distributed vendored source remains hash-verified. Keep the fallback and original files while release activation precedes Next restart.

## Editor snapshot (master f8ccb0536, LOWA r8)

The vendored editor (`useZetaOfficeWebview`, `libreofficeExecutorClient`, `editor-main`, `office_thread`, `zeta` and their imports) is the main repository's master at `f8ccb05363fbe0a94c215059ff10c3e0eb731ce1`, replacing the earlier 0.60.0 snapshot plus the PR #1275 IME backport (master contains it as squash commit `8ba45cb6f`). New imports since 0.60.0 are vendored unchanged: `zetaOfficeSelectionDrag.js` and the `zh-CN` / `en-US` editor locale modules used by the semantic writing panel. The engine is LOWA `24.2.8-zhcn-r8`; its decoded wasm/data hashes match the r8 table in the core repository's `desktop/lowa-build/RECIPE.md`.

The upstream entry also lists nine multilingual fallback fonts (Korean, Thai, Khmer, Lao, Myanmar, Arabic, Devanagari; dev-board#1478) that the desktop build bakes. The workbench does not pin or serve them, so `scripts/build.mjs` removes exactly those nine `fontUrls` entries (`omitUnservedFonts`, failing on drift) instead of letting the editor request nine URLs that 404. The upstream boot already treats missing category fonts as absent and its fallback chains skip them, so Chinese/Latin rendering is unchanged; those scripts render with whatever fallback the engine has.

`src/editor-capabilities.json` lists the editor actions the vendored executor accepts (`EDITOR_ACTIONS`), with the source commit and engine version. Regenerate it with `node scripts/editor-capabilities.mjs` after any vendor update; `npm test` fails when it drifts. The backend WEB tool allowlist is checked against this file.
