# Donation 入口与弹窗修复（2026-09-23）

关联开发看板 #830、#831、#832。用户在官网上线过程中反馈弹窗顶部被裁切，要求支持按钮外露，并明确要求国际站也提供无需登录的捐赠支付。

- 根因：Dialog 的 fixed 容器嵌在带 backdrop-filter 的固定导航内，定位包含块变成导航。改为 portal 到 body，限制视口边距与最大高度，内部滚动；保留现有 Dialog API，补关闭键、焦点返回与键盘约束。
- 三站导航直接提供支持 / Donate；窄屏可直接点击心形按钮，360px以上同时显示文字，不必展开菜单。
- 大陆沿用微信 Native 二维码；国际生成 Stripe Checkout 链接二维码，也可直接进入托管收银台填卡。二维码用于打开收银台，其他支付方式由 Stripe 按配置与访客条件展示。
- 无需账户。国际此入口显式创建匿名订单，即使浏览器已登录也不绑定账户，便于扫码手机无需登录查询回执；单笔 US$1–500，支持订单不增加 Credits。既有未传匿名标志的 API 保持登录订单属主规则。充值与购买仍要求登录，原回跳保持账户页。
- 捐赠回首页弹窗，保留国际/美国原域名，带 site=intl 防止跨设备回跳被地域分流；仅以服务端查询或经签名验证的支付事件确认成功，不相信 URL 的 success。补 Stripe 异步到账事件，复用金额、币种和幂等结算。
- 国际现有 Stripe webhook 已追加 async_payment_succeeded 订阅并 GET 核验，旧订阅均保留。凭据原位读取，配置摘要回写 EXTERNAL_SERVICES.md。

验证：大陆17项/国际18项支付回归通过（隔离数据库、合成签名和mock出站）；TypeScript通过。浏览器5种视口弹窗定位与横屏滚动、手机金额换行、Escape与回焦通过；国际前端模拟验证最低金额、匿名support建单参数、二维码、成功回跳服务端核实、取消、保留无关参数和关闭后停止轮询。未实付，不能把模拟结果当成真实入账验证。生产建单/收银台及部署验证结果记在开发看板。
